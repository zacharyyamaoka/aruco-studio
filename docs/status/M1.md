## One slip: bytecode caches in REF

The REF runs used `python -I` (isolated) with `PYTHONDONTWRITEBYTECODE=1`. `-I` ignores every `PYTHON*` variable, so Python 3.11 wrote its bytecode caches next to the REF modules it imported, in REF's git-ignored `__pycache__` folders. `git status` cannot see them, so the before / after check passed.

| What | Detail |
|---|---|
| Files | 12 `*.cpython-311.pyc` under `CADExporter/bam_cad_core/__pycache__/` (aruco_autosize, aruco_label, aruco_numbering, aruco_slabs, aruco_trim, print_beds, ...), `ArucoMarkers/__pycache__/` (aruco_presets, aruco_prusa, aruco_preset_library), `tests/__pycache__/` (aruco_label_fixtures, test_aruco_output), `tools/__pycache__/` (make_label_rule1_golden), written 15:59-16:48 |
| Effect | none on behaviour: they are caches of the same sources for Python 3.11 (Fusion runs 3.14 and keeps its own `cpython-314` files); any Python run would write them |
| Left as they are | deleting them would be one more write into REF; they are safe to delete by hand at any time |
| Fixed | both tools now start the child with `python -I -B` and set `sys.dont_write_bytecode`; `ref_path.new_bytecode()` fails a run that leaves bytecode for a file it read. Checked: `-I -B` writes no cache, `-I` with the variable alone does |
